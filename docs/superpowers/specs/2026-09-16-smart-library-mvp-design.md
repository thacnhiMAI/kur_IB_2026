# Спецификация MVP: «Умная библиотека»

## 1. Цель

Создать первую рабочую версию веб-приложения «Умная библиотека» как полноценный full-stack продукт на `Next.js`, где основной пользовательский сценарий строится вокруг каталога книг и персональных ИИ-рекомендаций.

MVP должен быть достаточно полным для демонстрации и защиты выпускного проекта, но без перегруза второстепенными подсистемами. В первую версию входят каталог, поиск, авторизация, профиль, избранное, отзывы, история взаимодействия с книгами, административное управление каталогом и модуль рекомендаций с абстрактным AI-слоем.

## 2. Границы MVP

### Входит в MVP

- публичная главная страница;
- каталог книг с фильтрацией по жанру, автору и году;
- поиск по названию и автору;
- карточка книги;
- регистрация и вход через `email/password`;
- вход через `OAuth`;
- профиль пользователя;
- избранные книги;
- отзывы и рейтинги;
- история взаимодействия с книгами;
- персональные рекомендации;
- административный CRUD для книг, авторов и жанров;
- seed-наполнение базы;
- деплой на `Vercel`;
- `README` с инструкцией запуска.

### Не входит в MVP-1

- `AR-preview` через `WebXR`;
- голосовой поиск через `Web Speech API`;
- `PWA`, offline-cache и push-уведомления;
- расширенная аналитика поведения;
- подписки, лайки и сложные социальные сценарии.

Эти функции проектируются как следующий этап развития после стабилизации базового продукта.

## 3. Архитектурный подход

Выбранный подход: **full-stack монолит на `Next.js` с чёткими границами внутренних модулей**.

Приложение разрабатывается как один репозиторий и один деплой, но внутренняя структура должна быть разделена по доменным зонам ответственности, чтобы проект было легко поддерживать и расширять.

### Технологический стек

- `Next.js` (`App Router`, `SSR`, `SSG`, `ISR`);
- `TypeScript`;
- `Prisma`;
- `PostgreSQL`;
- `Auth.js`;
- `Tailwind CSS`;
- `Zod`;
- `Vitest` или `Jest` для unit/integration тестов;
- `Playwright` для smoke e2e;
- `OpenAI` и/или `GigaChat` через единый `AIProvider`.

### Внутренние модули

- `auth` — пользователи, сессии, вход, регистрация, OAuth, роли;
- `catalog` — книги, авторы, жанры, фильтрация, поиск, карточки;
- `reading-history` — сигналы взаимодействия пользователя с книгами;
- `favorites` — избранные книги;
- `reviews` — отзывы и рейтинги;
- `recommendations` — логика агрегации пользовательских сигналов, вызов AI и fallback;
- `admin` — защищённое управление каталогом.

## 4. Рендеринг и маршрутизация

### Публичные страницы

- `/` — главная;
- `/catalog` — каталог;
- `/books/[slug]` — карточка книги.

Для публичных страниц используется комбинация `SSG/ISR`, чтобы ускорить загрузку, улучшить SEO и повысить показатели `Lighthouse`.

### Персонализированные страницы

- `/profile`;
- `/favorites`;
- `/recommendations`;
- `/admin/books` и связанные формы.

Для персонализированных и защищённых страниц используется `SSR` и серверная логика с проверкой сессии и роли пользователя.

## 5. Модель данных

### Основные сущности

#### `User`

Содержит профиль пользователя, email, хеш пароля, роль, имя, изображение профиля и настройки.

#### `Account`, `Session`, `VerificationToken`

Стандартные сущности `Auth.js` для поддержки сессий и OAuth.

#### `Book`

Основная карточка книги:

- `title`
- `slug`
- `description`
- `coverImage`
- `year`
- `isbn`
- `language`
- `pages`
- `publishedAt`

#### `Author`

Сущность автора книги.

#### `Genre`

Сущность жанра книги.

#### `BookAuthor`

Промежуточная таблица для связи many-to-many между книгами и авторами.

#### `BookGenre`

Промежуточная таблица для связи many-to-many между книгами и жанрами.

#### `Review`

Отзыв пользователя о книге:

- `userId`
- `bookId`
- `rating`
- `content`
- `createdAt`
- `updatedAt`
- `status`

#### `Favorite`

Фиксирует факт добавления книги в избранное конкретным пользователем.

#### `ReadingHistory`

Хранит историю взаимодействий:

- просмотр карточки;
- интерес к книге;
- отметка как прочитанная;
- дополнительные события, полезные для рекомендаций.

#### `RecommendationSnapshot`

Сохраняет результат рекомендации для пользователя, чтобы:

- не вызывать AI на каждый запрос;
- показывать стабильный результат;
- облегчить fallback;
- упрощать демонстрацию на защите.

### Правила модели данных

- у книги должен быть уникальный `slug`;
- книга может иметь нескольких авторов и несколько жанров;
- пользователь может иметь не более одного активного отзыва на книгу;
- пользователь может добавить книгу в избранное только один раз;
- рекомендации должны ссылаться на набор рекомендованных книг и краткое объяснение, почему они были выбраны.

## 6. AI-слой и рекомендации

### Архитектура AI

Для ИИ используется абстрактный интерфейс `AIProvider`.

Планируются как минимум два адаптера:

- `OpenAIProvider`;
- `GigaChatProvider`.

Остальная система не зависит от конкретного провайдера и работает только через единый контракт.

### Логика рекомендаций

1. Система собирает сигналы из:
   - `ReadingHistory`;
   - `Favorite`;
   - `Review`;
   - жанровых и авторских предпочтений пользователя.
2. `recommendations`-модуль нормализует эти данные.
3. Формируется контекст и запрос к `AIProvider`.
4. AI возвращает подборку книг и краткие объяснения.
5. Результат сохраняется в `RecommendationSnapshot`.
6. UI показывает рекомендации и объясняет, почему книги были предложены.

### Fallback

Если внешний AI-провайдер недоступен, приложение должно показать рекомендации по правилам без LLM:

- книги тех же жанров;
- книги схожих авторов;
- популярные книги с высоким рейтингом;
- книги, близкие к уже добавленным в избранное.

Fallback обязателен, чтобы рекомендации не зависели от доступности внешнего API во время демонстрации.

## 7. Основные пользовательские сценарии

### 7.1 Гость просматривает каталог

Пользователь открывает сайт, видит главную страницу, переходит в каталог, применяет фильтры и открывает карточки книг.

### 7.2 Пользователь регистрируется или входит

Поддерживаются:

- регистрация и вход через `email/password`;
- вход через `OAuth`.

После успешной аутентификации пользователь получает доступ к персональным функциям.

### 7.3 Пользователь взаимодействует с книгами

На карточке книги пользователь может:

- добавить книгу в избранное;
- оставить отзыв и рейтинг;
- отметить прочтение или интерес;
- тем самым сформировать сигналы для будущих рекомендаций.

### 7.4 Пользователь получает рекомендации

Пользователь открывает страницу рекомендаций и видит подборку книг на основе собственного поведения и предпочтений.

### 7.5 Администратор управляет каталогом

Администратор создаёт, редактирует и удаляет книги, авторов и жанры через защищённый интерфейс.

## 8. Страницы MVP

- `/` — главная;
- `/catalog` — каталог с фильтрами и поиском;
- `/books/[slug]` — карточка книги;
- `/auth/sign-in` — вход;
- `/auth/sign-up` — регистрация;
- `/profile` — профиль;
- `/favorites` — избранное;
- `/recommendations` — рекомендации;
- `/admin/books` — список книг в админке;
- `/admin/books/new` — создание книги;
- `/admin/books/[id]/edit` — редактирование книги;
- дополнительные административные формы для авторов и жанров.

## 9. Требования к интерфейсу

- UI должен быть современным, чистым и понятным;
- ключевой визуальный акцент делается на карточках книг и удобстве каталога;
- страница книги должна быть центральной единицей контента;
- рекомендации должны отображаться не просто списком, а с кратким объяснением выбора;
- административная часть может быть визуально проще, чем публичная, но должна быть полной функционально.

## 10. Безопасность и контроль доступа

- действия изменения данных доступны только аутентифицированным пользователям;
- административные маршруты доступны только пользователям с ролью `ADMIN`;
- все входные данные валидируются на сервере;
- авторство отзывов, избранного и истории взаимодействия должно проверяться по сессии, а не по клиентским данным;
- чувствительные ключи AI-провайдеров и БД хранятся в переменных окружения.

## 11. Качество и тестирование

### Цели качества

- `Lighthouse > 85` для публичных страниц;
- корректная работа каталога, фильтров и поиска;
- устойчивость к временному отказу AI-провайдера;
- воспроизводимый локальный запуск через `README` и seed.

### Обязательные тестовые сценарии

- регистрация и вход;
- доступ к защищённым страницам;
- фильтрация каталога;
- добавление книги в избранное;
- создание и отображение отзыва;
- формирование рекомендаций;
- fallback рекомендаций без AI;
- базовый smoke e2e для главных маршрутов.

## 12. Наполнение и демонстрация

Для MVP требуется seed-набор данных:

- книги;
- авторы;
- жанры;
- тестовые пользователи;
- администратор;
- достаточно данных для демонстрации рекомендаций.

Seed должен позволять продемонстрировать проект сразу после установки без ручного заполнения базы.

## 13. Деплой

Целевой деплой — `Vercel`.

Требования к деплою:

- корректная работа `Next.js` SSR/SSG;
- подключение к `PostgreSQL`;
- настройка переменных окружения;
- возможность повторного деплоя после обновления кода;
- открытый репозиторий с понятным `README`.

## 15. Критерий готовности MVP

MVP считается готовым, если:

- пользователь может зарегистрироваться и войти двумя способами;
- каталог книг работает с фильтрами и поиском;
- карточки книг содержат полную информацию;
- пользователь может добавлять книги в избранное и оставлять отзывы;
- система собирает историю взаимодействия;
- рекомендации доступны и через AI, и через fallback;
- администратор может управлять каталогом;
- приложение разворачивается локально и деплоится на `Vercel`;
- репозиторий содержит рабочий `README`.

## 16. Следующий этап после MVP

После завершения MVP-1 следующими отдельными спецификациями планируются:

- `AR-preview` через `WebXR` и `Three.js`;
- голосовой поиск через `Web Speech API`;
- `PWA`, offline-режим и push-уведомления;
- расширенные рекомендации и аналитика.
